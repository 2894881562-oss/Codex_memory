# 真实跨账户闭环验收

本方案验证另一账户是否能依据共同本地记忆继续工作，并把新内容写回，供下一次读取。它不把“同库的模拟客户端能读取”算作“真实第二个 OpenAI 账户已接通”，也不靠关键词命中宣布模型理解完美。

本阶段 2026-10-04 的只读核查中，运行库没有 ChatGPT 会话或 ChatGPT 原始档案；工程目录中未发现官方导出或第二账户人工验收结果。[本机交付记录](LOCAL_VERIFICATION.md)也明确：扩展未安装配对、第二账户尚未验收。因此下列真实路径当前均为 `pending`，不能改写为已完成。

## 准备与证据范围

需要用户提供官方 ChatGPT 导出文件的位置，手动加载扩展并复制本地配对令牌，确认自己正在使用两个不同账户，并明确允许哪些测试片段送入第二账户。无需 API Key，不向工程或验收者提供 OpenAI 密码、Cookie、登录 token、浏览器个人资料或整个记忆库。

使用同一个明确的 `--data-dir` 和本次独立项目标签，创建唯一运行编号，例如 `验收日期-自选随机字符`；下文所有 `<...>` 都需要由操作者填写。账户标签是 `ACCOUNT_A` / `ACCOUNT_B` 一类本地别名，标签不同并不证明登录账户不同。真实性证据由用户确认实际切换 / 登录情况和执行时间，可使用经遮蔽的界面证据，不能使用凭据作为证明。

先在 `exports/acceptance/<日期>-<运行编号>/` 保存人工报告和必要证据。这一路径被 Git 忽略；填写后的报告、交接包、原文片段和截图都不能放进 `docs` 或 Git。仓库只保留空白[结果模板](CROSS_ACCOUNT_RESULT_TEMPLATE.md)。证据使用必要的短片段、哈希、引用 ID 和操作记录，不默认复制整段私人聊天。

当前可用命令如下；导入和生成交接包须在明确选择来源及允许分享片段后执行：

```powershell
$AcceptancePython = '.\.venv\Scripts\python.exe'
$AcceptanceData = 'D:\Codex\Codex_memory\data'
$AcceptanceProject = '<本次验收项目标签>'
$AcceptanceTask = '复述当前目标、用户明确偏好、关键决策、阻塞和下一步；逐项引用真实检查点或消息 ID，未记录的内容明确说未知。'
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData stats
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData import-chatgpt '<用户明确指定的官方导出.zip>' --account ACCOUNT_A --project $AcceptanceProject
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData list --source chatgpt --account ACCOUNT_A --project $AcceptanceProject
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData project state $AcceptanceProject
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData handoff --project $AcceptanceProject --conversation-id '<列表中明确选中的测试会话内部 ID>' --task $AcceptanceTask --output '<工程内 exports\acceptance\本次目录\handoff-A-001.md>'
```

`--task` 是当次检索目的，不会自行变成长期偏好、用户授权或检查点。需要保存的目标 / 偏好 / 决策仍要在明确记录中表达。以上占位路径不能原样执行；已有输出不会覆盖。

官方导出可能含与测试无关的私人聊天。生成后先在本地审阅交接内容，确认只分享已经允许的片段；指定测试会话 ID 能缩小选择，但不应代替内容审阅。若包含不必要信息，停止发送，调整会话 / 任务选择或只提供人工确认的必要来源片段，绝不默认上传整库。

## 先建立人工核对基准

从用户允许的实际消息和最新检查点中选出少量事实，填入结果模板。至少覆盖：目标、明确偏好、关键决策、已知阻塞和下一步；每条包含原来源 ID、字段 / 必要短引用、时间和是否仍有效。偏好必须来自用户明确表达，不能把助手猜测当作偏好；没有明确记录的偏好，其正确答案就是“未记录 / 不能确认”。

核对基准应另行保存在本地，不能将整份标准答案塞进测试提问，再把复述标准答案算作检索成功。模型只能获得待测交接内容和用户明确允许的检索工具。若某关键事实未被交接选入，应记录召回缺口，允许模型按 ID 检索补足；普通 ChatGPT 无工具时，由操作者补发允许的短来源片段，并在报告注明。

## 路径一：官方导出与实时采集的同 ID 连续性

1. 在真实账户 A 的普通稳定聊天中发送 `跨账户验收/<运行编号>/A/初始`，并明确记录一个安全的新任务状态。取得包含该聊天的真实官方导出，导入时始终使用同一账户 / 项目标签。
2. 从导入列表记录内部会话 ID，并核对官方导出的外部会话 / 消息 ID。官方 ZIP / JSON 的 SHA256、导入报告和测试消息引用写入本地证据；导出里无该测试聊天时，这步为 `pending`，不能拿合成 JSON 替代官方导出。
3. 用户加载 / 配对扩展后，在同一个 `/c/<id>` 聊天发送 `跨账户验收/<运行编号>/A/实时`。记录扩展最近成功写入时间、账户 / 项目标签、消息 ID，并通过搜索核对入库。只记录状态，不复制配对令牌。
4. 确认官方导入与 DOM 采集引用同一会话；对于同一条可修订回复，检查最终正文和旧修订。若 DOM 只能提供 fallback 身份，记录这个限制：不能宣称已经证明官方导出 / DOM 消息 ID 精确合并。
5. 再导入包含后续消息的较新官方导出，核对同 ID 增量、不重复、最新文本不回退。重新导入旧导出时也不能覆盖较新的实时版本。未取得较新导出时，增量覆盖验证独立标 `pending`，其他已测步骤可保留结果。
6. 做一次短暂断开 / 恢复，核对已进入持久队列的唯一短句最终写入；未写入或 ID 冲突记为 `failed`。等待扫描完成，不使用固定三秒作为通过 / 失败门槛。

此路径只证明被选出的实际导出与已打开渲染聊天连续性，不能外推到关闭、临时、已删除、手机或其他未渲染历史。

## 路径二：真实第二个 ChatGPT 账户

由用户确认进入真实账户 B；先在扩展设置点击暂停、核对并必要时手动重试旧队列，再更新标签。保存新标签仍保持暂停，旧队列仍归原标签；关闭旧账户页面，切换网页账户，勾选确认后启用并刷新 B 的目标聊天页。弹窗主动探测服务在线，但过去成功时间或在线本身都不证明 B 消息已经入库。选择原验收项目，在弹窗填写当前任务，读取本地记忆、审阅并勾选分享确认后复制 / 粘贴。也可以上传已经人工确认允许的交接文件；报告必须区分“扩展读取”与“手动文件上传”，不能以一种路径的成功宣布另一种已通过。

在 B 的新聊天发送下列测试要求：

> 只依据提供的本地记忆及允许调用的读取工具，复述当前目标、用户明确偏好、关键决策、阻塞和下一步。每项给出实际出现的检查点 ID、消息 ID或已归档文件来源；区分用户事实、助手建议和未知。不要声称已经保存全部历史、迁移原生 Memory / 侧栏，或已经完成没有证据的第二账户验收。先确认上下文，不执行未授权工程变更。

人工逐项对照基准并核实引用。记录实际回答的必要短片段和错项；不是只检查答案里是否出现“无需 API”这几个字。模拟客户端、一个账户里两次聊天，或者仅仅更改标签，都不算真实第二账户证据。

## 路径三：真实第二个 Codex 账户

用户在实际第二个账户打开同一工程，通过自己安装的本地 MCP 或明确读取交接包继续。MCP 使用同一 `data-dir`；可以调用 `resume_project(project=<标签>, task=<本次问题>)`，再检索引用。没有 MCP 时用上面的 `handoff --task` 命令。

在新的 Codex 聊天执行同样的五类事实复述，分别记录读取方式、账户切换的人工作证、答案和引用。此前 stdio / HTTP SDK 测试属于“模拟同库客户端”证据，它们证明协议与存储读取，不替代此路径。ChatGPT 路径通过也不会自动使 Codex 路径通过。

## 新任务、回写与第三次读取

在已验收复述的 B 聊天中，由用户明确提出一个安全新任务，例如 `跨账户验收/<运行编号>/B/新任务：下一步先核对离线队列恢复证据`。检查扩展或 Codex 日志采集的这条真实消息已入库，引用标注为 B，而非 A。

用户核实后追加一份检查点，记录新任务、已完成事实、仍未完成的账户步骤和更新后的下一步。默认 MCP 只读时通过本地仪表盘 / CLI 明确保存；不能将“模型说已保存”当作实际写回。可用命令：

```powershell
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData checkpoint $AcceptanceProject --goal '<仍有效的目标>' --completed '<实际核实的完成项>' --decisions '<明确决策及偏好>' --next-steps '<带本次 B 唯一短句的更新下一步>' --blockers '<仍存在的阻塞>' --account ACCOUNT_B
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData search '跨账户验收/<运行编号>/B/新任务' --account ACCOUNT_B --project $AcceptanceProject
& $AcceptancePython -m codex_memory --data-dir $AcceptanceData project state $AcceptanceProject
```

第三次读取使用一个新的 A 或 B 聊天，不需要购买第三个账户。让它重新从同库取当前任务交接，指出最新检查点和 B 新消息的来源，复述更新后的下一步。新旧检查点都应留存；最新状态不能回退到 A 的初始状态。报告分别记录“真实新消息入库”“检查点落库”“第三次正确读取”，三项缺一不能宣布闭环通过。

## 错误断言和过度声称检查

对每个真实路径加入以下核对：

- 询问“是否已经保存本账户全部手机、临时与已删除聊天，且原生侧栏 / Memory 已迁移？”正确答复应区分已验证范围与不支持 / 未验证范围，不能回答全部已完成。
- 基准中的真实偏好若无来源，不能编造；引用不存在的消息 / 检查点，引用虽存在但支持不同事实，以及把助手旧建议当成用户当前决定，都记录错误。
- 让模型指出新增 B 任务与旧 A 下一步的差别；不能让旧导出或旧助手断言覆盖最新明确检查点。
- 检查它是否把账号别名、模拟 SDK、静态单测或 DOM fallback 当成真实第二账户 / 精确全量迁移证明。
- 检查它是否声称无需人工安装配对、无需给云端提供上下文、无需任何读取动作就能直接访问 D 盘。实际路径要求必须保留。

不能把检测到某些危险短语就自动判 `failed`：模型可能是在否定该断言。应保存具体必要片段、对应基准来源及人工判断；关键词工具只能提示人工审查。

## 结论与额度中断

每条路径分别选择 `pending`、`failed` 或 `passed`。缺输入 / 未执行 / 未验证为 `pending`，真实执行出现不符合判据且有证据为 `failed`；只有真实账户事实、技术保存、语义复述、引用核实及新任务回写 / 第三次读取都完成人工核对，才把该真实路径标 `passed`。官方导出增量、扩展与文件路径也分别记录，不做一项通过覆盖全项目的总括结论。

可以对五类事实各记“缺失 / 错误、部分 / 不可核实、正确且有支持引用”，但分数只帮助定位，不会自动证明理解完美。重大矛盾、虚假覆盖声称或伪造引用不能被其他得分抵消。

若 Plus / Codex 额度不足或模型提示限额，保存阶段总结：当前路径、最后成功步骤、最新检查点 / 消息 ID、未完成项、下一次动作、是否已写回和本机采集服务是否仍运行。相关未完成步骤保持 `pending`，恢复后从这些证据续测。额度未知时记录“未知”，不能把猜测的重置时间当事实，也不能声称已经建立自动限额监控；本工程没有这种自动监控机制。
