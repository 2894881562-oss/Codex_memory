# 0.1.0 验证范围

本记录描述工程检查的覆盖，不包含真实聊天、账户凭据或用户档案。完整验收步骤见 [ACCEPTANCE.md](ACCEPTANCE.md)，最终测试数量与发布包以构建时的命令输出为准。

## 独立检查已完成

- 文档命令形式通过当前 CLI 参数解析；这项检查没有执行导入、账户设置或其他动作。
- 扩展检查通过，包括页面稳定会话 / 首页跳过、流式消息修订、离线队列恢复 / 合并、队列已满时保留已有数据，以及带配对令牌的明确续接读取。
- 4 个 JavaScript 文件通过 `node --check`；3 个 PowerShell 脚本通过语法解析；扩展 Python 测试通过 Ruff lint 与格式检查。
- 当前备份源码使用受限内存 SQLite 快照 / 校验，加密 ZIP 在内存构建；没有明文备份暂存数据库 / ZIP 和恢复校验临时文件。运行记忆库仍默认明文。
- 当前备份输入上限：SQLite 2 GiB、单个原始档案 512 MiB、总展开内容 8 GiB、加密 ZIP 512 MiB；峰值内存可能高于单份文件大小，仍需足够可用 RAM。
- 恢复的来源标记 `needs_confirmation` 并暂停，用户明确重新添加同一来源配置才启用，避免备份中的不可信路径触发自动本地读取。
- MCP 会话读取有正文预算与截断标记，长消息可通过 `fetch_message` 的字符偏移分块读取索引；原始档案不会由这些工具直接返回。
- 当前 Codex 持续同步源码校验旧前缀，归档追加后缀与 SHA256 链清单，完整上下文解析用于正确去重；只向索引提交新增行。项目标签可按 `cwd` 目录名推断，也可明确覆盖。

## 必须分别验收

全套导入 / 核心 / HTTP / MCP / 备份测试应运行 `scripts/Test.ps1` 并查看实际结果。真实 Chrome / Edge 安装配对、当前 ChatGPT DOM、后台标签页行为和第二个 Plus 账户续接，不能由模拟扩展测试证明，需要按验收指南实测。

默认 3 秒是上一轮扫描完成后的等待间隔，较大首次导入可能需要数分钟。对当前未打开、未渲染或不落盘的内容没有全量实时覆盖承诺。跨普通 ChatGPT 账户使用扩展明确读取与复制 / 粘贴交接；跨本地 Codex 客户端使用同一库的 MCP；本工程没有自动部署公网 MCP 或迁移 OpenAI 原生 Memory / 聊天侧栏。
