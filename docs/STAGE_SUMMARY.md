# 记忆继承优化阶段 · 0.2

当前阶段重点是让新账户读取可追溯的个人记忆与任务证据，不要求现在就准备第二账户。本文件仅记录工程状态，不包含私人聊天正文或凭据；实际个人记录在被 Git 忽略的本地库中。

## 本阶段已实现

- 个人记忆按稳定键和项目范围保存：待确认、确认、撤回；只有用户消息来源支持的确认项默认参与继承。跨账户标签更新同一记忆，追加原件及修订链，不覆盖旧档案。
- 交接可指定当前任务；依据任务、最新目标、决定与下一步选择较早消息，提供内部消息 / 会话 ID，并保留有界同分支邻近上下文。文件索引排在证据后，引用不能挤掉实际命中正文。优先用户 / 助手对话，重复窗口折叠；无相关对话才后备工具输出，推理 / 状态日志不装入默认交接。
- CLI、管理面板、扩展读取与 MCP 统一传递任务；新增个人记忆阅读和显式保存入口，MCP 默认只读。不会自动发送、确认偏好或读取登录凭据。
- 提供真实跨账户验收方案及空白报告模板；区分第二账户理解、续接、实时保存、回写和再次读取，不把模拟标签或本地客户端当作真实验收。
- 延续 Python 标准库核心、SQLite 与不可覆盖原始档案，不调用推理 API，不迁移云端 Memory / 账户权限，不执行批量删除。

## 下一阶段 / 待验收

## 中断 / 额度规则

代理在阶段检查点读取可用的账户额度工具，任一相关窗口剩余≤10%或明确达到限额时不启动新工作，先追加工程检查点并给简短总结。无法读取时只能记录“未知”；平台突然中断可能来不及发送最终消息。不会消费重置券、购买额度或抓取私有额度接口。本地归档服务无需模型额度，不因工程代理暂停而自动停止。
